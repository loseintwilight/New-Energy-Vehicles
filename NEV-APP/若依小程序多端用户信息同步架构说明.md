# 若依小程序多端用户信息同步架构说明

## 一、为什么若依自带的「小程序模式」无法实现多端用户同步？

### 1.1 若依默认架构的单用户端局限性

若依框架（RuoYi）默认的移动端实现（包括 `uni-app` 小程序）基于以下设计前提：

| 维度 | 若依默认实现 | 本项目需求 |
|------|-------------|-----------|
| 用户角色 | 单一用户端（普通用户） | 用户端 + 充电桩商家 + 卖车商家 + 维保商家 |
| 数据源 | 仅 PC 端后台管理 | PC 端 + 各商家端共享同一数据库 |
| 状态管理 | 无跨页面数据同步机制 | 需要多页面、多端即时同步 |
| API 集成 | 未适配移动端编辑接口 | 需要 `getUserProfile` / `updateUserProfile` / `uploadAvatar` 完整链路 |

**核心问题**：若依自带的 `pages/mine` 页面通常只有「展示」功能，头像和用户资料编辑依赖 PC 端管理后台完成。小程序中缺少：

- 真实调用的 `getUserProfile` API（展示页仅使用模拟数据）
- 真实调用的 `updateUserProfile` API（编辑页仅用 `setTimeout` 模拟保存）
- 真实调用的 `uploadAvatar` API（头像上传页仅用 `setTimeout` 模拟）
- 编辑后的跨页面数据刷新机制

### 1.2 若依框架对「多商家端」的支持缺失

若依的设计中，不同商家端（充电桩、卖车、维保）通常通过不同的路由或角色切换入口进入。但默认模板中：

- 每个商家端的 `dashboard` 页面没有展示当前登录用户信息的区域
- 没有从 Vuex 读取并同步用户状态的机制
- 各端之间数据相互独立，无法实现「任一端编辑 → 所有端即时更新」

## 二、为什么 PC 端可以切换小程序，但小程序不能切换自身？

### 2.1 PC 端切换小程序的实现原理

PC 端（管理后台）通常通过以下方式「切换小程序」：

1. **小程序管理后台** → 选择不同的小程序 AppID 进行发布管理
2. **不同入口链接** → 根据用户角色跳转到不同的小程序页面
3. **WebView 嵌套** → 在一个 App 内加载多个小程序环境

本质上，PC 端的「切换」是 **服务端路由分发**，不涉及运行时的用户状态切换，只是加载了不同的页面集合。

### 2.2 小程序无法「自切换」的原因

微信小程序存在以下限制：

| 限制项 | 说明 |
|-------|------|
| **单 AppID 单实例** | 一个微信小程序只能对应一个 AppID，运行时无法动态切换 |
| **无运行时重载机制** | 小程序启动后无法「切换到另一个小程序」并保持状态 |
| **页面栈受限** | `switchTab` / `navigateTo` 只能在当前小程序内跳转 |
| **无法跨 AppID 跳转并传参** | `navigateToMiniProgram` 只能跳转另一个小程序，无法「融合运行」 |

### 2.3 本项目中的「伪切换」方案

本项目中的「切换端」实现（如 `mine/index.vue` 中点击「切换商家版」）实际上只是：

1. 修改 Vuex 中的 `currentEnd` 状态变量
2. 调用 `switchTab` 或 `reLaunch` 跳转到商家端的首页
3. **所有端共享同一个 Vuex Store**，因此用户数据在切换后仍然可用

**这不是真正的小程序切换，而是同一小程序内的页面路由切换。**

## 三、完善方案：如何实现全面的多端用户信息同步

### 3.1 架构总览

┌─────────────────────────────────────────────────────────┐
│                   微信小程序（单一 AppID）                  │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │

### 3.2 数据流设计

```
编辑流程（任一端均可发起）：
  用户点击头像/名字 → 跳转至 info/index（资料展示页）
                                      ↓
                     跳转至 info/edit（资料编辑页）或 avatar/index（头像编辑)
                                      ↓
                     调用 API → 更新数据库（PC 端同步）
                                      ↓
                     更新 Vuex（commit SET_NAME / SET_AVATAR / SET_PHONENUMBER）
                                      ↓
                     navigateBack 返回原页
                                      ↓
                     原页 onShow 触发 → 从 Vuex 读取最新数据 → 界面即时刷新

关键代码路径：
  1. api/system/user.js       → 定义 3 个 API 函数
  2. store/modules/user.js    → 定义 state、mutations、actions
  3. info/edit.vue            → getUserProfile 加载 + updateUserProfile 保存 + commit
  4. avatar/index.vue         → uploadAvatar 上传 + commit SET_AVATAR
  5. 各商家端 onShow          → this.$store.state.user.xxx 同步到本页面 data
```

### 3.4 已完成的改造内容

1. **`info/edit.vue`**：从模拟数据改为调用 `getUserProfile` 加载真实数据，调用 `updateUserProfile` 保存至数据库，保存后 commit Vuex 实现跨端同步
2. **`avatar/index.vue`**：从模拟上传改为调用 `uploadAvatar` API 上传至后端，保存后 commit `SET_AVATAR`
3. **`info/index.vue`**：添加 `onShow` 生命周期，每次页面显示时刷新数据
4. **`mine/index.vue`**：在 `onShow` 中添加 Vuex 同步，确保用户端编辑后返回即时刷新
5. **`vehicle-dashboard.vue`**：新增用户信息行（header 下方），在 `onShow` 中从 Vuex 同步数据
6. **`charge-pile/dashboard.vue`** 和 **`business-view.vue`**：将用户信息从 header **上方** 移动到 header **下方**，符合用户需求
7. 所有商家端页面均已添加 `goToAvatar()` → `/pages/mine/avatar/index` 和 `goToInfo()` → `/pages/mine/info/index` 跳转方法

### 3.5 注意事项

- **API 接口依赖**：确保后端已实现 `/system/user/profile`（GET 获取、PUT 更新）和 `/system/user/profile/avatar`（POST 上传）接口
- **头像 URL 处理**：后端返回的相对路径需要通过 `baseUrl` 拼接；`uploadAvatar` 返回的 URL 直接存入 Vuex
- **token 有效性**：所有接口依赖登录 token，未登录状态下应提示用户登录
- **Vuex 持久化**：`store/modules/user.js` 的 mutations 同时写入 `storage`（localStorage/uni-storage），确保页面刷新后数据不丢失

## 四、头像上传失败的原因与修复

### 4.1 问题现象

点击保存头像时提示「头像上传失败，请重试」，但服务端未返回有效错误。

### 4.2 根本原因

**原因一：上传文件字段名不匹配**

| 端 | 文件字段名 | 代码位置 |
|------|-----------|---------|
| PC端（正常） | `avatarfile` | `ruoyi-ui/src/views/system/user/profile/userAvatar.vue` → `formData.append("avatarfile", data)` |
| 小程序端（错误） | `avatar` | `api/system/user.js` → `name: data.name`（值为 `'avatar'`） |
| 后端（唯一接受） | `avatarfile` | `SysProfileController.java` → `@RequestParam("avatarfile") MultipartFile file` |

后端 `SysProfileController.java` 规定上传文件参数名必须为 **`avatarfile`**，但小程序端通过 `uploadAvatar({ name: 'avatar' })` 发送了 `avatar`，导致后端无法接收文件，返回错误。

**原因二：响应字段读取不正确**

PC 端代码：
```js
this.options.img = process.env.VUE_APP_BASE_API + response.imgUrl
store.commit('SET_AVATAR', this.options.img)
```

小程序原代码：
```js
const newAvatar = response.data || response.imgUrl || response.url || this.avatarUrl
```

后端返回格式为 `{ code: 200, imgUrl: "/profile/avatar/2024/xxx.jpg", msg: "success" }`，其中 `imgUrl` 是**相对路径**，需要拼接 `baseUrl` 才能得到完整 URL。原代码既没有优先读取 `imgUrl`，也没有拼接 baseUrl。

### 4.3 修复方案

**修复 1** — `api/system/user.js`：
```javascript
export function uploadAvatar(data) {
  return upload({
    url: '/system/user/profile/avatar',
    name: 'avatarfile',       // ← 改为 avatarfile 匹配后端
    filePath: data.filePath
  })
}
```

**修复 2** — `pages/mine/avatar/index.vue`：
```javascript
import config from '@/config'

uploadAvatar({ filePath: this.avatarUrl, name: 'avatarfile' }).then(response => {
  // 后端返回 imgUrl（相对路径），拼接 baseUrl
  const newAvatar = response.imgUrl ? (config.baseUrl + response.imgUrl) : (response.data || response.url || this.avatarUrl)
  this.$store.commit('SET_AVATAR', newAvatar)
})
```

### 4.4 排查步骤（供以后遇到类似问题参考）

1. **检查后端接口签名** → 确认 `@RequestParam` 的 value（这里是 `avatarfile`）
2. **检查前端上传字段名** → 确认 `uni.uploadFile` 的 `name` 参数是否与后端一致
3. **检查后端响应格式** → 确认返回的 JSON 字段名（这里是 `imgUrl`）并在前端正确读取
4. **检查 URL 类型** → 相对路径需要拼接 `baseUrl`，绝对 URL 可直接使用
