# 济南新能源汽车综合服务平台 —— 数据库逻辑设计

---

## 一、表数量统计（22张业务表）

| 模块分类 | 表数量 | 业务表列表                                                   |
| -------- | ------ | ------------------------------------------------------------ |
| 用户中心 | 4      | user_profile, user_favorite, user_feedback, user_address     |
| 车辆购车 | 6      | vehicle（含SKU）, vehicle_spec, vehicle_finance_plan（全款+分期）, vehicle_used, vehicle_review（单图）, unified_order |
| 充电服务 | 6      | charging_station, charging_pile, charging_rate, charging_rate_period, charging_order, charging_settlement |
| 维保服务 | 2      | maintenance_shop, maintenance_order                          |
| 碳积分   | 1      | carbon_ledger                                                |
| 政府功能 | 2      | carbon_statistics（碳排放大屏）, gov_nev_registration（车辆注册统计） |
| 商户管理 | 1      | merchant                                                     |
| **合计** | **22** | —                                                            |

## 二、模块逻辑关系

### 2.1 用户中心

```
sys_user（若依框架内置用户表，用户身份核心）
  │
  ├── 1:1 ── user_profile        → 用户扩展信息（身份证、碳积分余额）
  ├── 1:1 ── merchant            → 商户认证（登录账号 → 商户身份）
  ├── 1:N ── user_favorite       → 用户收藏（车辆/文章/充电站，多态关联）
  ├── 1:N ── user_feedback       → 用户反馈（提交意见 → 管理员回复）
  ├── 1:N ── user_address        → 收货地址（购车下单时选择）
  ├── 1:N ── unified_order       → 下单购车/试驾/以旧换新
  ├── 1:N ── charging_order      → 扫码充电
  ├── 1:N ── maintenance_order   → 预约维保
  ├── 1:N ── vehicle_review      → 发表车辆评价
  └── 1:N ── carbon_ledger       → 碳积分流水
```

**逻辑说明**：用户注册登录后，通过 `user_profile` 扩展实名认证和碳积分账户；`user_favorite` 通过 `target_type + target_id` 实现多态收藏（一辆车、一篇文章、一个充电站）；`user_address` 支持多地址管理，购车下单时选择；`user_feedback` 支持用户提交意见反馈并等待管理员回复。

### 2.2 车辆购车

```
vehicle_brand（品牌/车系树，自引用 parent_id）
  └── 1:N ── vehicle             → 车辆核心信息（新车+二手车统一存储）
                │
                ├── 1:1 ── vehicle_spec              → 配置参数（续航/电池/充电时间）
                ├── 1:N ── vehicle_finance_plan      → 金融方案（全款+分期，多套可选）
                ├── 1:1 ── vehicle_used              → 二手车专属信息（里程/电池SOH/估值）
                ├── 1:N ── vehicle_review            → 用户评价（含单图）
                └── 1:N ── unified_order             → 订单（购车/试驾/以旧换新）

merchant
  ├── 1:N ── vehicle              → 商户发布车辆
  └── 1:N ── unified_order        → 商户订单
```

**逻辑说明**：`vehicle_brand` 通过 `parent_id` 自引用实现品牌→车系二级树；`vehicle` 表通过 `vehicle_type` 字段（new/used）统一存储新车和二手车，避免两套表维护；新车通过 `vehicle_spec` 展示续航/电池等配置，通过 `vehicle_finance_plan` 提供多套金融方案对比（全款 vs 分期）；二手车通过 `vehicle_used` 记录里程/过户次数/电池健康度（SOH）/估值价格；`unified_order` 统一承载购车、试驾、以旧换新三种订单类型，以旧换新通过 `old_vehicle_id → new_order_id` 自关联实现。

### 2.3 充电服务

```
merchant
  └── 1:N ── charging_station     → 充电站（含入驻审核+地图展示）
                │
                ├── 1:N ── charging_pile          → 充电桩（独立状态监控+实时心跳）
                ├── 1:N ── charging_rate          → 费率组（区分快充/慢充）
                │            └── 1:N ── charging_rate_period → 费率时段（峰谷平+工作日/周末/节假日）
                └── 1:N ── charging_order         → 充电订单

charging_settlement               → 按商户+日期维度的结算单（含提现）
```

**逻辑说明**：`charging_station` 含经纬度+GeoHash 支持附近搜索，含入驻审核字段（营业执照/场地证明）；`charging_pile` 独立记录每根桩的实时状态（空闲/充电中/离线/故障），通过 `last_heartbeat` 心跳超时自动标离线，通过 `access_type` 区分公用/专用/自用桩，用户可按标签筛选可用桩；`charging_rate` 按桩类型区分快充/慢充费率组；`charging_rate_period` 按 `price_type` 区分工作日/周末/节假日+峰谷平时段，充电时系统自动匹配对应电价；`charging_order` 记录充电全程（起止SOC/电量/费用/碳积分），关联费率组实现计费溯源；`charging_settlement` 按商户+日期汇总结算，内嵌提现流程。

### 2.4 维保服务

```
merchant
  └── 1:N ── maintenance_shop     → 维保门店（地址拆分+经纬度）

sys_user
  └── 1:N ── maintenance_order    → 维保订单
                ├── → maintenance_shop（门店）
                └── → vehicle（车辆）
```

**逻辑说明**：商户入驻后可创建多家维保门店（`maintenance_shop`），地址按省/市/区拆分支持区域筛选；用户通过 `maintenance_order` 在线预约维保，关联门店+车辆+服务项目，评价信息直接内嵌在订单表中（`rating + comment_content`），无需独立评价表。

### 2.5 碳积分

```
carbon_ledger（积分流水账：source_type+source_id 可溯源）

user_profile.balance               → 当前积分余额（写入流水时同步更新）
```

**逻辑说明**：`carbon_ledger` 记录每笔积分变动（`record_type` 区分获得/消耗/兑换），通过 `source_type + source_id` 溯源到具体业务订单（充电订单/购车订单/阅读文章/签到）；积分发放规则由代码层配置管理，规则参数可灵活调整无需建表。

### 2.6 政府功能

```
carbon_statistics               → 碳排放/充电统计（按日期+城市+区县维度聚合）
gov_nev_registration            → 新能源车注册统计（按日期+城市+区县维度统计）
```

**逻辑说明**：`carbon_statistics` 按日期+城市+区县维度汇总充电运营核心指标（充电站数/桩数/充电量/碳减排量/等效植树量/碳积分发放兑换）；`gov_nev_registration` 按日期+城市+区县维度统计新能源车注册数据（当日新增/保有量/BEV/PHEV/FCEV分布），供政府大屏实时展示。

### 2.7 商户管理

```
merchant
  ├── → sys_user（1:1 关联登录账号）
  ├── 1:N ── vehicle              → 发布车辆
  ├── 1:N ── charging_station     → 运营充电站
  ├── 1:N ── maintenance_shop     → 运营维保门店
  ├── 1:N ── unified_order        → 订单关联商户
  └── 1:N ── charging_settlement  → 充电结算
```

**逻辑说明**：`merchant` 与 `sys_user` 1:1 绑定登录账号，`merchant_type` 区分经销商/充电运营商/维保商；包含完整的入驻审核（营业执照/法人信息）、状态管理（待审核→已入驻→已停用）、资金账户（累计收入/已结算/待结算/已提现）。
